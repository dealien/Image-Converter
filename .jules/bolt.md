## 2024-04-04 - Pillow ImageEnhance Overhead vs LUT Native Execution
**Learning:** `ImageEnhance.Contrast` computes blending over split channels, recalculating math operations pixel-by-pixel within standard enhancement methods, scaling with image size. In `L` or `RGBA` modes, handling alpha channels dynamically causes substantial performance degradation. The result varies based dynamically per image instead of statically mapping colors as `ImageEnhance.Color` would. Actually, `ImageEnhance.Contrast` maps to blending between the original image and a solid color image filled with the image's mean luminance!
Wait, actually `ImageEnhance.Contrast` evaluates the target color statically (gray), BUT `ImageEnhance.Contrast` relies on blending with the mean luminance.
**Action:** When implementing contrast/brightness changes with `ImageEnhance`, be aware that using `getdata()` on `ImageEnhance.Contrast(L_Image)` allows caching the transformation array for that factor globally, bypassing the heavy overhead of splitting and merging channels. However, `getdata()` is deprecated; use `list(enh.getdata())` carefully and suppress the `DeprecationWarning` for Pillow <14 or try to use `get_flattened_data` where available.

## 2024-04-04 - Deprecation in Pillow 14 `getdata()`
**Learning:** `Image.getdata()` is deprecated and raises a `DeprecationWarning`, scheduled for removal in Pillow 14.
**Action:** In operations requiring extracted pixel sequences from an image, attempt using `get_flattened_data()` if the version allows, or suppress the warnings for backwards compatibility if relying on `getdata()`.
